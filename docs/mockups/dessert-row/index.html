Adding a “Dessert” meal type

The week grid’s label column is only 20pt wide, so “De” doesn’t fit — that constraint drives the whole choice. All three keep Dessert as a fourth row after Dinner. Shown at true iPhone 13 mini width (375pt), the smallest screen we support.

A · Icons in the label column recommended

Replaces the B/L/D letters with small glyphs. Solves the D-vs-D collision outright, reads instantly, and needs no extra width. Cost: letters are a familiar anchor, and you lose them for all four rows.

C · Dessert is opt-in

Grid stays 3 rows by default; a Household setting adds the Dessert row for people who want it. Keeps the daily view uncluttered for those who don’t plan dessert. Cost: a settings toggle to build and explain, and the feature is invisible until found.

One thing worth knowing before you pick: whichever option we take, the database change is the same — meal_type is a Postgres ENUM, so Dessert means ALTER TYPE meal_type ADD VALUE 'dessert'. That is a one-way change: Postgres cannot remove a value from an enum, so backing it out later means rebuilding the type. Worth being sure before it ships.
